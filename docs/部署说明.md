# 部署说明

> **目标一句话**：把应用从 `localhost:3000` 部署到**一台香港云服务器**，
> 让评委打开一个**干净网址** —— `https://ai-web.work`，**不带端口、带 HTTPS、带 HTTP/2**。

**要跑的命令都在 `deploy/` 里，这份文档说的是"为什么"和"顺序"。**

---

## 一、架构

```
                    ┌──────────────────── 一台香港 ECS（免备案）──────────────┐
   评委的浏览器      │                                                       │
  https://ai-web.work ──▶ Caddy :443 ──▶ Nuxt :3000（systemd 常驻，只监听回环）│
        （h2）         │      自动 HTTPS / 自动续期 / 自动 h2                   │
                    └───────────────────────────────────────────────────────┘
                                     │
                                     └──▶ DeepSeek（生成）+ 智谱（向量检索）
```

**应用代码一行没改**：Nuxt 还是跑 3000，只是把外面接 80/443 的活儿交给了 Caddy。

---

## 二、为什么这么选（答辩能直接用的三条）

1. **必须 HTTP/2**：浏览器在 HTTP/1.1 下同源最多 6 条连接，而我们的产品要并发发多条流式请求
   （压缩包入口是「一个文件一路」）。本地实测：并发 10 比并发 5 慢 **1.7 倍**，并发 40 慢 **6 倍** ——
   卡的就是这 6 条连接，服务端和上游全程没吃力。
2. **HTTP/2 必须 HTTPS → HTTPS 必须有被信任的证书 → 证书必须有域名**。这是一条链，不是三个独立选择。
3. **Caddy 把"证书 + HTTP/2"全自动化了**：配置只有 3 行。少一处人工配置，就少一处演示当天出事的可能。

**为什么不用 Nginx**：Nginx 要手写证书路径、手写续期定时任务、还要记得 `proxy_buffering off`
（不关就会把我们的流式输出攒成一次性吐出，打字机效果直接没了）。
**为什么不用 Cloudflare 在最前面再加一层**：Caddy 已经给了证书和 h2，多一层只会在流式这条命门上多一个
"缓冲行为只能靠猜"的环节。

## 三、一次性步骤（只做一次）

### 1. 买服务器（人做）

香港地域，Ubuntu 22.04 64 位，**预装应用一个都不选**。
（宝塔面板自带 nginx，会占掉 80/443，和 Caddy 撞车。）

### 2. 安全组放行 80、443（人做）

控制台 → 实例 → 网络与安全组 → 安全组 → 配置规则 → **入方向** → 手动添加：

```
协议类型 TCP    端口范围 80/80     授权对象 0.0.0.0/0
协议类型 TCP    端口范围 443/443   授权对象 0.0.0.0/0
```

**出方向不用动**（默认全放行）—— 服务器要主动出去调 DeepSeek / 智谱、拉 git、装包。

> SSH(22) 和 ICMP 那两条默认规则**留着别动**：前者用来登录，后者用来 ping 排查。
> 阿里云默认还会给一条 RDP(3389)，那是给 Windows 实例的，Linux 上没有程序监听它，建议删掉。

### 3. 域名解析（人做）

云解析 DNS → `ai-web.work` → 解析设置 → 添加记录：

```
记录类型 A   主机记录 @     记录值 <服务器公网IP>     TTL 默认
记录类型 A   主机记录 www   记录值 <服务器公网IP>     TTL 默认
```

⚠️ **加之前先看 `@` 这个主机记录下已经有没有 A 记录。**

云解析同一主机记录下有多条 A 时按**轮询**分发（这是免费版唯一的负载策略）——
如果 `@` 下同时存在旧 IP 和这台服务器的 IP，**访问者会有一半概率被送到旧机器上**。
所以 `@` 下只允许留一条 A 记录，多出来的要删掉。

⚠️ **非 A 类型的记录（NS / TXT / MX / CNAME）一律不要动** —— 那些通常是域名实名验证或邮箱用的，
删了可能连域名解析一起停掉。

### 4. 克隆仓库并初始化服务器（服务器上，root）

```bash
git clone https://github.com/skf-123/AI-We.git /opt/ai-web
cd /opt/ai-web
bash deploy/install-server.sh
```

这个脚本装 Node 22、装 Caddy、建一个专用的 `aiweb` 用户、把配置放到位并 enable 服务。
**它不启动服务** —— 因为还没有密钥文件。

### 5. 传密钥文件（本地执行）

`.env` 被 `.gitignore` 排除，**永远不进仓库**，所以它要单独传：

```bash
scp -i ~/.ssh/ai-web-deploy .env root@<服务器公网IP>:/opt/ai-web/.env
```

然后在服务器上收权限：

```bash
chown aiweb:aiweb /opt/ai-web/.env && chmod 600 /opt/ai-web/.env
```

> systemd 的 `EnvironmentFile` 直接读这个文件，所以 **unit 文件里没有任何明文密钥**，
> 那个文件可以随便看、可以进 git。

### 6. 首次部署（服务器上）

```bash
bash /opt/ai-web/deploy/deploy.sh
```

## 四、以后每次更新代码

本地推送到 GitHub 之后，在服务器上跑**同一个脚本**：

```bash
bash /opt/ai-web/deploy/deploy.sh
```

它会：拉最新代码 → 装依赖 → 构建 → 重启服务。服务器上不写代码，所以直接对齐远程分支。

## 六、已知的坑（都踩过或查过）

| # | 坑 | 后果 | 怎么避 |
|---|---|---|---|
| 1 | **服务器上直接 `npm ci` 或 `npm install`** | Linux 上装不上原生包，构建第一步 `nuxt prepare` 就失败（`Cannot find module @rolldown/binding-linux-x64-gnu`） | **要「删干净再装」**：`rm -rf node_modules package-lock.json && npm install --legacy-peer-deps`。<br>**为什么不能只换 `npm install`**：锁文件是 Windows 上生成的，带着它装,npm 不会去取 Linux 的原生二进制；而删掉锁文件让 npm 重新解析，又会撞上 arborist 解析 Nuxt peer 依赖图崩溃（`Cannot read properties of null (reading 'edgesOut')`）。`--legacy-peer-deps` 跳过 peer 解析正好绕开那一处。**这两件事必须一起做**，`deploy.sh` 里已经写死<br>**还要配上 npm ≥ 12**：npm 自己的可选依赖 bug（npm/cli#4828）会**间歇性**发作 —— 同一条命令手动跑成了、脚本里跑就报 `Cannot find native binding`。10.9.9 上如此，升到 12.2.0 后没再出现。`deploy.sh` 开头会检查并自动升级<br>想在 Windows 上提前发现问题：`npm ci --dry-run --ignore-scripts --os=linux --cpu=x64 --libc=glibc` |
| 2 | **安全组没放行 80/443** | 域名解析对了也打不开，一直转圈 | 见第三节第 2 步 |
| 3 | **`@` 下多条 A 记录** | 访问者一半概率被送到旧 IP | 见第三节第 3 步 |
| 4 | **`flush_interval` 写了也没用** | —— | 官方文档写明：Content-Length 未知的响应一律立即 flush，我们的流式响应正是这种。**写了会被忽略，还附带"客户端断开也不取消后端请求"的副作用**，所以不写 |
| 5 | **给流式响应开 gzip** | 压缩要攒内容，打字机效果没了 | 不写 `encode` 指令 |
| 6 | **反复重签证书** | 撞 Let's Encrypt 限流（同一域名 7 天最多 5 份） | 调试阶段先在 Caddyfile 里加 `tls internal` 或 `acme_ca` 指到 staging，别拿正式环境试错 |
| 7 | **Node 版本不够** | Nuxt 直接拒绝启动 | nuxt 4.6.1 要求 `^22.22.3 ‖ ^24.15.0 ‖ >=26.0.0`。`install-server.sh` 会拦住低于 22.22.3 的情况 |
| 8 | **用内地服务器** | 80/443 会被备案系统拦 | 所以我们选香港（免备案） |

## 七、环境变量

全部通过 `/opt/ai-web/.env` 控制，模板见仓库根目录 `.env.example`。**两组 key 完全分开、互不回退**：

| 变量 | 用途 |
|---|---|
| `NUXT_LLM_API_KEY` / `_BASE_URL` / `_MODEL` | DeepSeek，负责生成解释文字 |
| `NUXT_EMBEDDING_API_KEY` / `_BASE_URL` / `_MODEL` / `_DIMENSIONS` | 智谱 `embedding-3`，负责把语料变成 1024 维向量 |
| `NUXT_RAG_ENABLED` / `_TOP_K` / `_MIN_SCORE` | 检索行为，有默认值（阈值 0.38 是探针实测校准出来的） |
| `NUXT_ASK_HISTORY_TOKENS` | 追问历史预算，默认 10 万 token |

> `NUXT_EMBEDDING_API_KEY` 缺失时，检索会**直接跳过**（降级为纯模型回答），
> 不会拿 LLM 的 key 去顶替 —— 两家的向量空间不通用，拿错只会得到 404。

## 八、出问题先看哪里

```bash
systemctl status ai-web          # 服务活着吗（有没有反复重启）
journalctl -u ai-web -f          # 实时日志，报错都在这
systemctl status caddy           # 证书申请成功了吗
journalctl -u caddy -n 50        # 证书失败的原因在这
curl -I http://127.0.0.1:3000/   # 应用本身通不通（绕过 Caddy）
```
