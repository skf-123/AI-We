# AI 调用与上下文设计

**一个模型，很多次独立请求：项目模式每个功能怎么占上下文**

作者：麦穗团队
2026-10-24

---

## 先说结论

项目模式不是「一个大模型从头做到尾」，而是「两个 Agent 循环 + 一串单次请求」。

服务端不存会话。每次请求该带什么，由前端带上来；模型本身不记得上一次。

每个请求有自己的 1M 上下文窗口和输出上限。不能把多次请求的上下文加起来算，也不能把多个功能的输出上限加在一起算。

只有「项目总览正文 + 项目图」共用一个上下文。其他功能之间只传数据，不共用上下文。

另外有一条只画图的路：用户在项目总览旁点「重新生成图」时，只发一次图请求，不重跑正文。它和汇总不共用上下文，只沿用同一份输入。

---

## 一、先分清四个词

| 说法 | 在这份文档里的意思 |
|---|---|
| **一次 AI 调用** | 向模型发一次请求、拿一次响应。 |
| **一个 Agent** | 多轮调用组成的循环。每轮把工具结果追加到同一个消息数组里，下一轮把整个数组重新发一遍。每轮仍然是一次新请求。 |
| **一个上下文** | 这一次请求里带了什么。1M 是模型单次请求的窗口，输入和输出都算在里面；本项目用的模型窗口约 100 万 token。 |
| **共用数据** | 把同一段字符串分别放进不同请求。比如每个逐文件请求都带同一段「项目结构结论」——这是数据复用，不是共用上下文。 |

> token 是模型计费和长度单位。中文大约 0.6 token 一个字，英文和代码大约 0.3 token 一个字符。

另外几个在本文里反复出现的词：

- **项目结构结论**：地图 Agent 跑完后，把项目概述、目录说明、文件说明、跨文件线索拼成的一段文字。逐文件请求把它原样带在代码前面，汇总也会带。
- **四段解析**：每个文件的讲解分四段——逐词逐句、局部关系、整段作用、技术溯源。
- **图自检**：汇总图出现后，再跑一轮 Agent，检查有没有浮着的文件、有没有只剩分组级的边；检查不过就保留原图。
- **前缀缓存**：同一段前缀在多次请求里重复出现时，上游可以复用之前的计算结果，减少重复计费。

## 二、调用模型的功能

| 功能 | 什么时候跑 | 上下文里装什么 | 输入上限 | 输出上限 | 上下文归属 |
|---|---|---|---|---|---|
| **项目侦查（地图 Agent）** | 选完文件夹自动 | 系统提示词 + 5 个工具定义（读目录、读文件片段、读配置、grep（按关键词搜文件内容）、知识库检索）+ 目录树 + 可读文件清单 + 每轮工具结果；每轮把累积消息重新发一遍 | 客户端 1.4M 字符 / 服务端 1.5M 字符 / 消息 10,000 条；目录树 ≤150k 字符；单次工具结果 12k–20k 字符 | 每轮 50,000 token、每轮工具 ≤20 个；最多 `min(需解析文件数, 100)` 轮 | 一次侦查一个会话；每轮是新请求；和其他功能不共用 |
| **固定地图回退** | Agent 失败 / 超预算 / 用户停止时 | 目录树 ≤200k 字符 + 最多 300 个文件头（每个 ≤600 字符） | 目录树 200k 字符；服务端允许 2000 条文件头 | 4,096 token；超时 60 秒 | 独立的一次请求；只是地图功能的备用路径 |
| **逐文件四段解析** | 点「开始解析」后，每个文件一次 | 系统提示词 + 项目结构结论 ≤50k 字符 + 当前文件完整代码 ≤50k 字符 + 知识库检索到的资料（topK 4，取最相关的 4 条） | 代码 50,000 字符；项目结构结论 50,000 字符；请求体允许 100,000 字符，实际截到 50,000 | 10,000 token；超时 120 秒；并发 HTTP/2 100 路 / HTTP/1.1 5 路 | 每个文件一个独立上下文；同一份项目结构结论重复发送 |
| **项目总览 + 项目图** | 全部落定后手动，或至少 2 个文件完成时提前生成 | 系统提示词 + 项目结构结论 ≤50k 字符 + 目录树 ≤200k 字符 + 每个完成文件的第三段 ≤300 字（合计预算 30 万字符）+ import ≤8 条 | 目录树 200k 字符；文件 2000 个；职责摘要字段（role）最多 2000 字符（客户端只发 300）；import 20 条、每条 500 字符（客户端只发 8 条） | 300,000 token；正文和图共用；超时 120 秒 | 正文和图共用这一次请求、这一个上下文；和其他功能不共用 |
| **只重画项目图**（可选） | 用户在项目总览旁点「只重画项目图」或「重画项目图」 | 上一次汇总冻结的项目结构结论 + 目录树 + 每文件第三段 ≤300 字 + import；有正文时一起带上，让图按正文分层 | 项目结构结论 50,000；目录树 200,000；文件 2000 个；正文 20,000 字符 | 300,000 token；超时只覆盖等响应头 | 独立的一次请求；和汇总不共用上下文，只沿用同一份输入数据 |
| **图自检（默认分批）** | 汇总图出现后自动；也可手动重跑 | 程序清单（每条边 / 结构项一行）+ 本批 8 项 + 涉及节点摘要 + 可读文件 + 项目结构结论 ≤20,000 字符；每批独立 | 总预算 500,000 token、预留 25,000、批池 475,000、单批 20,000、硬停 525,000；每批工具 6（硬顶 8）；单次输出 50,000；未归属 ≤64、缺边 ≤40、证据包每次 5 条 / 24,000 字符 | 每批一次请求，批间不共享对话；和地图 Agent 不共用 |
| **图自检（旧路径，`?selfcheck=legacy`）** | 地址栏加参数 | 系统提示词 + 工具定义 + 项目图 + 项目结构结论 + 文件清单 + 工具结果；每轮重发累积消息 | 同 Agent 的 1.4M / 1.5M / 10,000 条；最多 20 轮、12 次工具；单次输出 50,000 | 一次长会话；和地图 Agent 不共用 |
| **项目追问** | 每次点发送；一问一次 | 系统提示词 + 当前文件代码 ≤50k 字符 + 选中片段 ≤2k 字符 + 刚生成的解析 ≤20k 字符 + 问题 ≤500 字符 + 历史（10 万 token，约 166,666 字符，从最近往前裁） | 代码 50,000；选中 2,000；解析 20,000；问题 500；历史 10 万 token | 5,000 token；不接知识库检索 | 每问一个独立上下文；历史由前端重新发；关掉气泡即清空 |
| **第三方库 AI 复核** | 上传后，对规则筛出的疑似候选 | 最多 40 个候选，每个文件头 ≤4,000 字符 | 候选 40 个；每个文件头 4,000 字符 | 1,536 token | 每次独立 |
| **系统文件勾选说明** | 勾选系统文件前 | 路径、标签、原因、大小 | path 1000；label 1000；reason 200 字符 | 160 token | 每次独立 |
| **知识库向量检索** | 逐文件解析时；地图 Agent 调 `search_knowledge` 时 | 查询文本；返回 topK 4（取最相关的 4 条），每条 800 字 | topK 4 | 不是对话输出 | 独立的 embedding（把文字变成向量，用来检索）请求；结果作为数据进入对应的大模型上下文 |

> 输出上限是单次请求的天花板，不是目标值。常规文件的实际输出由提示词里的篇幅要求决定，通常远低于上限。

### 项目追问的输入与输出（完整预算）

追问每问一次就是一次独立请求。它不和任何其他功能共用上下文；当前文件、选中片段、刚生成的解析和历史，都是作为数据重新带上去的。

输入：

| 项 | 上限 | 约 token（0.3 / 0.6 换算） | 占 1M |
|---|---:|---:|---:|
| 系统提示词 | 固定，约 520 字符 | 约 150–310 | 0.015%–0.03% |
| 当前文件代码 | 50,000 字符 | 15,000–30,000 | 1.5%–3.0% |
| 选中片段 | 2,000 字符 | 600–1,200 | 0.06%–0.12% |
| 刚生成的解析 | 20,000 字符 | 6,000–12,000 | 0.6%–1.2% |
| 问题 | 500 字符 | 150–300 | 0.015%–0.03% |
| 历史 | 100,000 token（约 166,666 字符） | 最多 100,000 | 10% |
| **合计（都按上限）** | — | **约 122,000–144,000** | **约 12.2%–14.5%** |

输出：

| 项 | 值 | 占比 |
|---|---:|---:|
| 输出上限 | 5,000 token | 占模型单次最大输出 393,216 的 **1.27%** |
| 输出上限 | 5,000 token | 占 1M 上下文窗口的 **0.50%** |

几条口径：

- 百分比是按单次请求、按上限算的，不是实际用量；一次追问不能和另一次追问的上下文相加。
- 历史从最近往前裁到 10 万 token 为止，至少保留一条；5,000 条只是畸形请求的护栏，不决定带多少。
- 5,000 token 只是上限，约 8,300 汉字；真正让回答短的是提示词里的「三五句话」，实际回答通常离这个上限很远。
- 问题框在页面上有 500 字符的输入限制；绕过页面直接调接口时，超过 500 会返回 400「问题太长了，请精简一下」。
- 追问目前没有「输出到达上限」的提示；如果回答真的撞到 5,000，页面上的回答会停住，这是已知缺口。

### 输出撞到上限时

逐文件解析和项目总览都是流式输出。上游最后一块数据会带一个停下来的原因；如果是「撞到最大输出」，服务端在流末尾追加一个不可见标记，前端去掉标记并在页面上提示：

- 逐文件：目录树标「输出超限」，解析面板末尾写「输出到达上限，后面的内容没有讲完」，面板标题加后缀。
- 汇总：正文或项目图可能不完整时，汇总区给一行提示；图区把「被输出上限截断」和「格式没解析成功」分开说。
- 只重画图：撞到上限时图区写「图内容太长，被输出上限截断」，旧图保留。

这样不会把一份被截断的解析，静默地当成已经讲完了。

## 三、不调用模型的功能

| 功能 | 说明 |
|---|---|
| 文件夹拖入 / 选择、1 GB / 50000 文件上限、读取状态 | 浏览器端；超过上限先挡一次 |
| 文件分类、目录树、1.9 MB 选中预算、勾选状态、配置角色 | 纯函数 + 页面状态 |
| 第三方库规则识别（三档） | 文件名、扩展名、文件头规则；AI 复核另行调用 |
| 地图证据核对 | 前端读文件，核对路径、行号、引文；允许行号偏 1–2 行 |
| 项目图渲染与交互 | Vue Flow（前端画图库）+ dagre（自动排版）；展开收起、全屏、分组归属虚线、大分组兜底 |
| 选中联动 | 正文选中 → 左栏代码行高亮；图里选分组 → 右侧显示对应文件 |
| 解析百分比、书本动画 | 按时间走的显示，不是真实进度 |
| Agent 轨迹展示 | 阅读版 / 开发者版；只是展示，不产生新上下文 |
| 未勾选重新生成、部分生成 | 复用汇总接口；输入数据变了，上下文结构不变 |
| 上传失败弹窗、系统文件确认弹窗、第三方库负结果文案 | 纯界面状态 |

## 四、哪些功能共用一个上下文，哪些各自独立

| 分组 | 包含哪些功能 | 关系 |
|---|---|---|
| **同一次请求** | 项目总览正文 + 项目图 | 共用同一个上下文和同一笔输出预算 |
| **同一个多轮会话**（每轮重新发累积消息） | 地图 Agent + 它的 5 个工具调用（含 `search_knowledge`） | 一次侦查一个会话；每轮是一次新请求；会话状态是累积的 messages |
| **同一个多轮会话**（另一个） | 图自检 + 它的工具调用 | 和图自检自己的 10 轮共用；和地图 Agent 不共用 |
| **每个文件一个独立上下文** | 逐文件四段解析 | 187 个文件就是 187 个上下文；它们只是共用同一段项目结构结论文字 |
| **每问一个独立上下文** | 项目追问 | 每次发送都是一次新请求；历史靠前端重新带上 |
| **每次独立** | 固定地图回退、只重画项目图、第三方库复核、系统文件说明 | 各自一次请求，互不共用 |
| **不占模型上下文** | 上传、目录树、分类、预算、图渲染、选中联动、动画、轨迹展示 | 纯前端状态与计算 |

## 五、数据是数据，上下文是上下文

```
地图 Agent（会话 A）
  └─ 产出项目结构结论 projectContext（一段文字）
       ├→ 逐文件解析（每个文件一个独立上下文 B1…Bn）
       │    └─ 每个文件的第三段摘要 → 汇总（上下文 C）
       ├→ 汇总（上下文 C）：正文 + 项目图 JSON
       │    └─ 项目图 → 图自检（独立会话 D）
       ├→ 图自检（会话 D）也重新带一份项目结构结论
       └→ 项目追问（每问一个独立上下文 E）：带当前文件代码 + 该文件的解析
```

几个容易误判的地方：

- 逐文件解析和汇总都带同一段「项目结构结论」，这是数据复用，不是共用上下文。逐文件请求这样做，是为了命中前缀缓存。
- 图自检拿的是汇总图，不是汇总的上下文；它自己重新带项目结构结论和文件清单。
- 追问拿的是当前文件的解析，不是逐文件解析的上下文；它把解析当数据重新发一遍。
- 地图 Agent 和固定地图是同一个功能的两种路径，但不是同一个上下文；固定地图只在 Agent 失败时跑。
- 项目地图（文件说明、跨文件线索）和项目图（汇总产出的那张图）不是一回事：前者来自地图 Agent，后者来自汇总调用。

## 六、为什么这样切

### 1. 失败隔离

一个文件解析失败，不影响其他文件；图 JSON 没解析成功，正文仍然保留。把功能拆成独立请求，坏掉一处不会把整页作废。

### 2. 并发与速度

逐文件解析可以并发（HTTP/2 100 路 / HTTP/1.1 5 路），不用等上一个文件结束。追问的输入小、提示词要求三五句话，所以回答快；输出上限 5 万只是保险丝，不是目标。汇总要等文件解析完才有每文件的第三段，所以放在后面。

### 3. 每笔预算独立

每个请求有自己的输出上限，不用和别的功能抢。地图 Agent 每轮 50,000，逐文件 10,000，汇总 300,000，追问 5,000，各管各的。

### 4. 前缀缓存

逐文件请求的 system 提示词固定、项目结构结论每字相同、文件代码各自不同。前缀一致，DeepSeek 的前缀缓存才可能命中，同一段项目结构结论不用重复计费。

### 5. 无状态与隐私

服务端不存对话。追问历史由前端保存、随每次请求带上；关掉气泡就清空。用户贴的代码只存在于当前页面和本次请求里，后端没有会话存储，部署也简单。

## 七、常见误解

| 问题 | 回答 |
|---|---|
| 你们是不是一次 AI 调用做完所有事？ | 不是。两个 Agent 循环 + 一串单次调用。sportboot（一个 Java 项目样本）那次实测：地图 Agent 7 轮 = 7 次调用，逐文件 2 个文件 = 2 次，至少 9 次独立调用。 |
| 逐文件之间共享上下文吗？ | 不共享。每个文件一次独立请求；它们只共享同一段项目结构结论字符串，模型 A 的讲解不会出现在模型 B 的上下文里。 |
| 地图 Agent 和逐文件共享吗？ | 不共享。地图 Agent 读了哪些文件、grep 到什么，不会传给逐文件；逐文件只拿到它最后那个 JSON 拼成的字符串。 |
| 项目总览和图是两次调用吗？ | 正常路径是一次：正文和图共用同一个上下文和同一笔输出预算。想只重画图时，会单独发一次图请求，正文不动。项目很大时，图 JSON 更容易先撞上限，页面会明确提示。 |
| 追问有记忆吗？ | 没有。每问一次都是新请求，历史由前端重新发；关掉气泡就清空。 |
| 两个 Agent 共用接口，是不是共用一个上下文？ | 共用接口和工具定义，但不共用上下文。每次 Agent 循环各起一份 messages。 |
| 1M 是所有功能加起来的预算吗？ | 不是。1M 是单次请求的窗口，每个请求各有一个；不能把多次请求加起来算。 |

## 九、版本说明

本文的数字取自 2026-10-24 的代码；同日增加了「只重画项目图」这条独立请求。之后如果调整上下文预算、输出上限或请求拆分方式，需要同步更新这张表和《追问上下文预算说明》《知识库设计说明》里对应的数字。
